# NEXVARY Avionics Lab — Stage Ledger 001–250

This ledger defines the first 250 engineering stages as 25 ten-stage release gates. A gate is marked complete only when its implementation is present in the repository and the cross-platform CI suite covers the resulting core.

> Scope: training, simulation, reliability engineering, HMI data models, synthetic telemetry, fault handling, and software verification. No targeting, weapons control, or real-world combat functionality.

| Stages | Gate | Delivered capability |
|---|---|---|
| 001–010 | Foundation | C++20/CMake project, namespace, build layout |
| 011–020 | Sensor bus | Thread-safe synthetic sensor publication/read/snapshot |
| 021–030 | Eventing | Severity model and event log |
| 031–040 | Liveness | Watchdog primitive and test coverage |
| 041–050 | Health baseline | Invalid-sensor, compute-temperature, power-voltage rules |
| 051–060 | Deterministic time | Simulation clock with controlled ticks |
| 061–070 | Scenario baseline | Nominal deterministic sensor generation |
| 071–080 | Synthetic flight data | IMU, altitude, airspeed, power, hydraulic, fuel channels |
| 081–090 | Fault injection | Invalidate, override, and offset fault modes |
| 091–100 | Power scenario | Timed simulated bus-voltage transient |
| 101–110 | Sensor dropout | Timed synthetic IMU dropout scenario |
| 111–120 | Thermal scenario | Progressive simulated compute thermal-rise scenario |
| 121–130 | Health alerts | Persistent/deduplicated active-alert model |
| 131–140 | Alert lifecycle | First-seen, last-seen, active/cleared history |
| 141–150 | Telemetry frames | Sequence/time-stamped sensor snapshots |
| 151–160 | Recorder | In-memory deterministic flight-data recording |
| 161–170 | Replay | Sequential replay cursor and reset semantics |
| 171–180 | Lab orchestrator | Clock + scenario + fault + health + alert + recorder pipeline |
| 181–190 | Cockpit data model | Unified LabSnapshot for future Qt/QML MFD bindings |
| 191–200 | Training console | Cross-platform cockpit-style system monitor output |
| 201–210 | CLI scenarios | Scenario selection, tick count, scenario listing |
| 211–220 | CLI replay | Recorded-frame replay summary mode |
| 221–230 | Defensive input | Bounded tick count and unknown-scenario failure handling |
| 231–240 | Verification expansion | Core, simulation, alert lifecycle test executables |
| 241–250 | Release gate | Windows/Linux CI, compiler warnings, scope documentation |

## Stage 250 exit criteria

- Project configures and compiles with CMake on Ubuntu and Windows runners.
- `core_tests`, `simulation_tests`, and `alert_tests` pass.
- Nominal scenario remains healthy for a 100-tick deterministic run.
- Fault scenarios create observable health alerts without crashing the simulation.
- Telemetry recording/replay remains deterministic and contains no live aircraft interfaces.
- The public API exposes a cockpit-friendly snapshot model ready for a Qt/QML HMI layer.
