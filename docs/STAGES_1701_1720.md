# Stages 1701–1720 — Diagnostic Intelligence Release

Status target: **NEXVARY Avionics Lab v3.2.0 / Stage 1720**.

Scope is strictly training/simulation with synthetic telemetry. These stages do not add live-aircraft I/O, flight control, weapons, targeting, guidance, firing, or OEM maintenance authority.

## Twenty-stage progression

1. **1701 — Diagnostic Evidence Model**: typed evidence, finding, severity and summary DTOs.
2. **1702 — Deterministic Finding Engine**: diagnoses synthetic state from telemetry, health model, recorder and events.
3. **1703 — Correlation & Deduplication**: repeated evidence for one code is merged rather than displayed as duplicate faults.
4. **1704 — Confidence & Priority**: every finding receives deterministic confidence and presentation priority.
5. **1705 — Recorder Integrity Diagnostics**: sequence and simulation-time monotonicity become diagnostic evidence.
6. **1706 — Health-Model Correlation**: SystemHealth issues are correlated to system-specific diagnostic findings.
7. **1707 — Diagnostic Health Score**: weighted 0–100 score based on ranked active findings.
8. **1708 — Portable Diagnostic Report**: round-trip JSON schema plus human-readable Markdown report.
9. **1709 — Baseline Comparison**: current scan versus baseline exposes new, resolved and persistent codes.
10. **1710 — Diagnostic Casebook**: versioned JSON case records for training investigations.
11. **1711 — Case Workflow**: DETECTED → ISOLATING → RECOVERING → VERIFYING → CLOSED state machine.
12. **1712 — Recurrence History**: first/last tick, scans seen and active state are tracked by code.
13. **1713 — Training Recommendations**: correlated recommendations are generated by system class.
14. **1714 — CLI Export Surface**: diagnostic JSON, Markdown, casebook and summary switches integrated into the executable.
15. **1715 — Qt Diagnostic Bridge**: the C++ diagnostic engine is exposed as typed QML rows and counters.
16. **1716 — Backend-Driven Diagnostic Center**: RUN DIAGNOSTIC ENGINE now calls C++ analysis instead of duplicating scan logic in JavaScript.
17. **1717 — Executive Diagnostic UX**: health score, ranked findings, confidence, priority, evidence and recurrence history appear in the UI.
18. **1718 — Automated Diagnostic Release Gate**: CI validates diagnostic schema, safety scope, Markdown and casebook artifacts on Windows and Linux.
19. **1719 — Package Governance**: Windows portable/installer packages include verified example diagnostic artifacts and versioned provenance.
20. **1720 — Release Identity & Visual Gate**: v3.2.0 / Stage 1720, updated screenshots for Executive, Engineering, Diagnostic EN/AR and Verification views.

## Diagnostic output contract

- Schema: `nexvary-avionics-diagnostic/v1`
- Casebook: `nexvary-diagnostic-casebook/v1`
- Scope: `training-simulation`
- Finding fields include code, system, category, severity, confidence, priority, probable cause, isolation guidance, recovery criteria and evidence.
- The diagnostic fingerprint is deterministic for the scenario/finding set and is intended for comparison and traceability, not cryptographic authentication.
